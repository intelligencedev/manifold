# Born Supertonic fork — in-process Go TTS (WIP)

Goal: run Supertonic's 4 ONNX graphs in pure Go via a fork of
[`born-ml/born`](https://github.com/born-ml/born) so Manifold can serve Supertonic
TTS in-process (no Python sidecar), behind the existing `/tts` contract.

`born-changes.patch` is a `git diff` against a fresh clone of `born-ml/born`
(v0.9.17). Apply with:

```bash
git clone --depth 1 https://github.com/born-ml/born.git
cd born && git apply /path/to/born-changes.patch
```

## Parity method (TDD)

`reference/harness.py` generates onnxruntime reference outputs and diffs them
against Born. Born-side trace: run the parity test with `BORN_TRACE=1` and grep
`^TRACE` into `born_trace.txt`. The `onnx/parity_supertonic_test.go` test loads a
graph in **strict** mode and compares `ForwardNamed` to the reference.

```bash
# reference (needs venv with onnx+onnxruntime+numpy, and models/ dir):
python harness.py gen-dp-ref
python harness.py dump-shapes models/onnx/duration_predictor.onnx
python harness.py dump-int64 models/onnx/duration_predictor.onnx
# born trace:
BORN_TRACE=1 SUPERTONIC_MODEL_DIR=$PWD/models SUPERTONIC_DP_REF=$PWD/dp_ref.json \
  go test ./onnx/ -run TestDurationPredictorParity 2>&1 | grep '^TRACE' > born_trace.txt
python harness.py diff-values born_trace.txt ort_int64_vals.json   # first wrong value
python harness.py diff-shapes born_trace.txt ort_shapes.json        # first wrong shape
```

## Done (all with unit tests; full Born suite still green)

New ops (in `internal/onnx/operators/ops_supertonic.go`):
- **Pad** — constant / edge / reflect modes.
- **Conv1d** — 3D NCL, intercepts `handleConv` when input is 3D. stride,
  asymmetric pads, dilation, groups/depthwise, bias. (Born's Conv2d rejects
  dilation>1, so a dedicated impl was required.)

Born core bug fixes:
- **ConstantOfShape** honored value-attr dtype (was hardcoded float32 → broke
  int64 shape math). `utility_ops.go`.
- **Clip** int64 support (was float32-only → panicked). `activations.go` +
  `clipInt64` in ops_supertonic.go.
- **Expand** ONNX bidirectional broadcast (errored 64→1). `shape_ops.go` +
  `onnxBroadcastShape`.
- **Empty-tensor support**: `Shape.Validate` allows 0-dims; `AsFloat32/64`,
  `AsInt32/64`, `AsBool` return nil on empty (were panicking on `&data[0]`);
  `Reshape` allows literal 0 dims. Updated the two Born tests that asserted the
  old "reject 0" contract.

Progress: `duration_predictor` (simplest graph) now runs through embedding, all
ConvNeXt blocks, and into the attention encoder.

### The buffer-aliasing bug (was the hard blocker — FIXED)

Born's inplace ops mutate a buffer when it looks unique (refCount==1), but a
tensor held in the graph executor's `tensors` map is still live — later nodes
read it. An inplace op consuming it corrupted it (e.g. a Clip output overwritten
with `17` before Unsqueeze/Slice read it → empty/garbage downstream). Fix
(`internal/onnx/model.go` `ForwardNamed`): a `put()` helper calls
`t.ForceNonUnique()` on every tensor placed in the map (weights, inputs, node
outputs), so inplace ops copy instead of corrupting. Root-caused via the
value-diff harness (`diff-values`), which pinpointed the first wrong int64 value.

Also added int64 `Pow` (integer shape arithmetic) to get dp over the line.

Ops now added: Pad, Conv1d, Clip(int64), Pow(int64), Sin, Cos, Reciprocal,
Softplus, Tile, BatchNormalization, ReduceSum — all with unit tests. Core fixes:
ConstantOfShape dtype, Expand broadcast, empty-tensor support (Shape.Validate,
AsX accessors, Reshape), the aliasing fix.

## ✅ PIPELINE PORT DONE & VALIDATED (pure-Go Supertonic works end-to-end)

Package `supertonic/` (in the fork) ports the full `helper.mjs` pipeline:
`assets.go` (tts.json / unicode_indexer / voice styles), `text.go`
(preprocess + tokenize + sentence chunking), `pipeline.go` (dp → text_encoder →
N-step flow-matching loop → vocoder, with noise injection hook), `wav.go`
(PCM16 + WAV). Public API: `supertonic.New(modelDir)` →
`tts.Synthesize(text, voice, Options) ([]float32, error)` + `FloatToPCM16` /
`WAVBytes`. CLI: `cmd/tts`.

Validation (`supertonic/pipeline_test.go`):
- `TestPreprocessAndTokenize` — tokenization of "Hello there." matches the
  captured `text_ids` exactly.
- `TestSynthesizeDeterministic` — injecting the captured initial noise
  reproduces the captured audio: **59173 samples, maxAbs 3.5e-5**. Validates
  tokenizer + dp + text_encoder + the 8-step loop + vocoder + slicing together.

NFKD normalization is omitted in `preprocessText` (identity for ASCII/Latin;
add `golang.org/x/text/unicode/norm` for full multilingual parity — the only
known gap).

  engine load. Full manifold `go build ./...` green.
2. **Performance** — two rounds done, verified at every step by the oracle
   property test (`TestConv1DMatchesReference`, 10 randomized configs, run
   under `-race`), all 4 graph parities (identical maxAbs), and the
   deterministic pipeline test (maxAbs 3.5e-5 unchanged throughout).
   - Round 1: parallelized the direct conv loop over (batch, out-channel) with
     work-sized worker count — 28s → 5.9s deterministic test (~4.7x).
   - Round 2: **im2col + blocked matmul** (`conv1DMatMulPath` in
     ops_supertonic.go): per-(batch, group) column tiles (`conv1DTileFloats`
     caps scratch at 4 MB; pooled), dilation-aware `im2colTile` with hoisted
     bounds (contiguous copy for stride 1 — pointwise ConvNeXt MLPs become
     plain copy+matmul), 4-row axpy kernel, (batch, group, col-tile, row-chunk)
     job queue on an atomic cursor. Depthwise/tiny convs stay on the direct
     path. Born's own MatMul/GEMM was NOT reused: SIMD gemm is amd64-only and
     MatMul is single-threaded. Result: 5.9s → 2.49s deterministic test.
   - Round 3: **4×4 register-tiled matmul kernel** in `runJob` (16 accumulators
     live in FP registers across the k-loop; C written once per tile).
     RTF 1.42 → 1.37.
   - Round 4: **BatchMatMul row-splitting parallelism** (`bmmParallelF32` in
     internal/backend/cpu/batchmatmul.go, wired into both the plain and
     broadcast float32 paths): small batch counts (the 4 attention heads)
     previously ran fully serial; (batch × row-chunk) jobs on an atomic-cursor
     pool now use every core. Deterministic test 2.31s → 1.43s.
   - **RESULT: RTF 0.76 — faster than real-time** (load 0.13s; 4.66s synth for
     6.14s audio on a 16-core M-series). Perf journey: RTF ~21 → 3.5 → 1.42 →
     1.37 → **0.76** (~28x total).
